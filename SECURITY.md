# Security Policy

## Сообщение об уязвимостях

Если вы обнаружили уязвимость, пожалуйста, **не создавайте публичный issue**.

Напишите на внутренний канал безопасности или напрямую владельцу проекта.

## Основные меры безопасности проекта

- **Supabase Row Level Security (RLS)** — все таблицы защищены политиками на уровне БД.
- **Серверные проверки** — `getSessionUser()`, `canAccessAllBranches()`, `assertBranchAccess()` в Server Actions.
- **Security Headers** — настроены в `next.config.ts` (X-Frame-Options, HSTS, Referrer-Policy и др.).
- **Multi-tenant** — каждый пользователь работает только в рамках своего `branchId`.

## Работа с секретами

- Никогда не коммитьте `.env.local`, `SUPABASE_SERVICE_ROLE_KEY` и другие чувствительные ключи.
- Используйте `.env.example` как шаблон.
- Service Role Key используется только в доверенном серверном коде (E2E setup, seed и т.д.).

## Зависимости

Мы регулярно обновляем зависимости. Для аудита используйте:

```bash
npm audit
```

Спасибо за ответственное отношение к безопасности!
