# Архитектура StaffEfficiency

## Введение

StaffEfficiency — это внутренний multi-tenant дашборд для компьютерного клуба. Проект построен на Next.js 16 (App Router) с акцентом на чистую архитектуру, безопасность и поддерживаемость.

После спринтов P1 и P2 архитектура была значительно улучшена: Server Actions стали тоньше, бизнес-логика вынесена в сервисы, добавлены системы Audit Log и Feature Flags.

## Основные принципы

- **Thin Server Actions** — Server Actions отвечают только за валидацию входных данных, вызов сервиса и side effects (revalidate, уведомления).
- **Сервисный слой** — вся бизнес-логика и авторизация сосредоточена в сервисах (`lib/*/ *.service.ts`).
- **Централизованная обработка ошибок** — через утилиту `withAction`.
- **Multi-tenant by design** — каждый пользователь работает в рамках своего `branchId`. OWNER имеет доступ ко всем филиалам.
- **Audit-first** — важные действия автоматически логируются.
- **Feature Flags** — возможность управлять поведением системы без нового деплоя.

## Multi-tenancy и безопасность

- Все сущности (Shift, Employee, InventoryItem и др.) содержат `branchId`.
- Авторизация выполняется на двух уровнях:
  1. **Supabase RLS** — на уровне базы данных.
  2. **Сервисный слой** — `assertBranchAccess()`, `requireUser()`, `canResetBonus()` и т.д.
- OWNER имеет `branchId = null` и доступ ко всем филиалам.
- SENIOR_ADMIN и ADMIN ограничены своим филиалом.

## Ключевые улучшения P1 и P2

- Server Actions стали тонкими и предсказуемыми.
- Появилась единая точка обработки ошибок.
- Вся важная бизнес-логика вынесена в тестируемые сервисы.
- Добавлена система аудита действий.
- Внедрена система feature flags для управляемого развития.
